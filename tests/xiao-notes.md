# 魈：实现与验证

- `fan_xiao`：男，吴，4体力，称号“护法夜叉”。牌面技能原文保留。
- 傩舞非锁定：`useCardToPlayered` 首目标事件询问一次，确认后标记所属 useCard，并将所有在场角色写入原生 directHit。多目标不重复询问，取消不写状态、不播音。
- `damageBegin1` 逐次以双方当前体力比较，目标体力不小于魈时伤害+1；只匹配同一 useCard 与同一牌，包括连环传导（传导继承原伤害数值后，再按各受伤者与魈的当前体力判断是否额外+1；各传导角色独立，不将上一名传导者新增的加伤滚入下一名）。嵌套用牌各自记录。加伤语音每张杀一次，与发动语音按原生媒体 ended/error 排队，规则结算不等待语音。
- `useCardAfter` 整张杀结算后只执行一次：魈在场且体力大于1时，先失去1体力，仍在场再摸1张，然后增加本阶段杀次数上限。正常使用次数仍照常统计，可多次叠加。未造成伤害或目标全取消不免除结算后效果；体力不大于1则整段不执行。阶段切换、回合结束或下一回合开始清理额外次数，避免跳过阶段残留。
- 降魔锁定：原生 maxHandcardBase 返回体力上限，仍按引擎叠加其他手牌上限修正；击杀来源的 dieAfter 回复1再摸2，满血仍摸牌。按原生击杀归属，不把助攻或失血死亡误归为魈击杀。
- 击杀发生于杀结算过程中，因此降魔先回复、摸牌，傩舞随后读取最新体力支付；1体力击杀后回复到2时，也会在该杀结算后失血到1并摸牌、增加次数。
- AI每张杀重新检查目标敌友、效果收益、当前体力、加伤条件、后续手牌杀及失血成本，并计入连环其他敌友及自身可能受到的额外加伤，不将偏好写入规则过滤。
- 配音完整保留11条原声：战技3、爆发3、闲聊2、倒下3；原声、来源网页、媒体接口响应、哈希及响度报告在 audio/xiao/originals。闲聊动态较大，受真峰余量限制约−18 LUFS；不压缩动态、不削波追平。逐条表见 audio/README.md。
- 立绘使用用户第二张原图，保留完整2500像素原画。对局360×492、选将180×246及详情1056×1100独立取景；归一化裁剪坐标与轻微低通参数见 originals/xiao-crops.json 与生成说明：小图裁剪后按原尺寸高斯0.65（原图小于2000px时0.4），Lanczos缩放；详情不加低通。
