# 优菈【浪花】实现与验证

女、群、4体力，武将 `fan_eula`，技能 `fan_langhua`；技能栏保留新版牌面原文。主技能及结算子技能明确 `locked: false`，非锁定且强制执行。

- 使用时：对应本地1.11.6 `content.useCard` 的 `useCard`，先于指定目标事件；固定点数、连续次数和累计档位，再摸牌。1张和2–3张仍在此处播放对应语音；4张以上此时不播音。
- 首张为0，比较成功加1，下降归0，跨回合保留。3、5、8、2、4、7对应0、1、2、0、1、2。仅统计本人使用，不统计打出和他人用牌。
- 单素材转化使用引擎实际点数。无点数不当作0，不比较成功并中断序列；此为实现口径，未加入牌面。
- 2档：每回合首次合格用牌在使用时预约“结算后获得护甲”，防止嵌套重复占用；即使已满5甲仍占用该回合资格。回合内历史限次，额外阶段不刷新，失去再获得技能不刷新。实际结算使用 `changeHujia(1, "gain", 5)`。
- 4档：每张合格牌结算后摸牌。结算节点为 `useCardAfter`，先加甲再摸牌；并不依赖素材进入弃牌堆。
- 6档：使用时增加该牌原生 `baseDamage`，增量为 `max(1, 点数-10)`；沿用原生多目标、重复结算、伤害增减和连环流程，不在伤害事件中查找“最近一张牌”。
- 使用时保存的外层牌档位不受嵌套牌中断序列影响。取消目标/整牌无效不退还连续次数或护甲资格；离场不再获得奖励。
- 4张起在结算后额外摸牌前播放mid池。6张起在该牌首次实际造成伤害（`damage`，正数且非unreal）时立即播放high池，不等待后续濒死处理及`damageSource`；多目标和重复结算不重播。结算后额外摸牌仍播放mid池。无伤害只播放mid池；0伤害、防止伤害、嵌套低档牌伤害不能误播。通过实际useCard父事件、用牌者和牌对象匹配快照。语音修改不改变规则及AI。
- 技能失效期间不执行主技能及结算子技能，不删除真实用牌历史。恢复后按实际相邻用牌比较；封锁期间没有技能快照的牌按引擎取值，动态改点数与封锁组合尚需真实对局验证。
- AI仅对原生可用且有正收益的牌偏好低点数起步、递增衔接；计入摸牌、护甲5点上限与低体力需求，增伤分别评估敌友和原生伤害收益；不将AI偏好写入合法性过滤。
- 原画原文件保存于 `image/character/originals/eula.png`，2500×2500。裁剪框 (500,70,2000,2170)，输出400×560至 `image/character/portraits/eula.png`；已查看脸部与上半身构图。

`node tests/eula.mjs`：持有技能展开真实group后模拟派发，覆盖首牌、相同点数、下降、跨回合、无点数、单素材转化、四档路由、嵌套快照、护甲限次/封顶/刷新、结算摸牌防重复、离场、失效及AI敌友/收益/上限。读取本地源码核对伤害基数初始化和传递。

`node tests/audio-layout.mjs`：调用本地原生Audio和trySkillAudio验证四档池、阵亡路径、语音开关、清单、来源文件与哈希。已通过JavaScript语法及音频解码检查。以上为模拟与本地方法验证，尚未进行实际对局、UI及游戏内听音测试。
