# 刻晴结算与验证

- 配置：群，女性，3体力、1护甲。技能名经用户确认是“苛捐”“雷厉”。技能栏逐字保留卡图原文。
- 苛捐在自己的 `phaseJieshuBegin` 询问；取消不播音、不取样。确认后从当时弃牌堆的黑色牌随机抽取至多三张，仅自己观看并强制选一张获得。没有黑牌不询问；不足三张展示全部。查看不移动牌、不改变弃牌堆顺序；获得前核对牌仍在弃牌堆且属于本次快照。随机取样为本次采用的实现口径，牌面不额外增字。
- 雷厉使用原生 `chooseToUse` / `chooseToRespond` 单素材转化流程，素材为自己的手牌或装备区装备牌，雷属性固定。保留原生距离、目标、禁用、素材合法性、装备目标数及响应上下文。没有素材时不能发动，取消选牌或目标不消耗、不播音。
- 同一回合使用和打出共用一次；`onuse` / `onrespond` 在原生提交时记录消耗，`phaseBefore`（下一回合开始）清除。额外出牌阶段不刷新；失去重获雷厉不会移除此回合使用记录。技能被暂时封锁时该非锁定技及其退计数子技能按原生封锁处理。
- 使用前，`cardUsable` 仅为本技能生成、实际由一张合格装备构成的杀放宽次数；原生按钮预检查使用 `unsure` 无素材虚拟牌，因此单独允许有装备时的该检查。普通杀、其他转化、混合素材不获豁免。提交后的 `useCard1` 退还引擎先增加的杀计数并将 `addCount` 设为 false；普通杀次数先用尽后仍可雷厉，先雷厉后仍保留正常次数。打出不会消耗正常使用杀次数，也会消耗雷厉额度。被无懈、闪、取消目标或无效不退还已经提交的技能额度。
- 玉衡是锁定技，监听 `useCardToTargeted`。本地享乐等原生“无效”技能使用相同节点：将刻晴加入该次用牌 `excluded`，保留原目标列表与使用记录。成为目标相关技能仍有发动机会；顺拆不对刻晴执行取牌或弃牌，其余目标照常结算。没有改成“不能成为目标”。
- AI：苛捐默认接受无代价收益并按当前牌价值选取；雷厉复用雷杀原生目标收益、敌友、距离、连环属性伤害及响应AI，以素材现值评估成本，每次重新检查可用次数与装备；玉衡用 `zerotarget` 消除对刻晴的牌效果估值，保留用牌者技能收益与其他目标收益，不写规则目标禁令。
- 语音：苛捐确认实际发动时播放一次；雷厉原生实际使用或打出时播放一次；玉衡确实对顺拆无效时播放一次。内部计数和刷新不播放。每技能两句独立随机池，阵亡单独原生播放。
- 立绘：原图 `image/character/originals/keqing.png` 2500×2500，裁剪框 `(640,180,2240,2420)`，输出400×560。根据对局截图反馈，将裁剪框向左移动160原图像素，使人物在武将框内向右移动约画框宽度的10%；缩放与纵向取景保持一致。已查看更新后的裁剪图，未进行游戏界面复查。
