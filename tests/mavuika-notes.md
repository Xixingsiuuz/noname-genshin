# 玛薇卡炽魂调整（2026-10-27）

2026-10-31 修复空确认残留：本地 `ui.click.ok()` 不传按钮节点时不关闭确认控件；最后一次 `game.check()` 又会创建控件。自动提交现与原生 `checkEnd.autoConfirm` 一致，在最终合法性检查后先关闭 `ui.confirm`，再提交原生用牌。此前测试仅验证提交次数，漏测控件生命周期；现补充模拟每次检查重建控件，并检查桃、酒、闪及打出杀提交后控件已关闭。主动杀仍保留目标选择。语法与交互/语音节点模拟通过，尚未游戏界面实测。

技能栏按新武将牌原文录入：“每当有【杀】进入弃牌堆，你获得1个‘战意’标记（至多4个），若数量超过上限则改为摸1张牌。每轮限一次，你可以移除1个‘战意’标记，视为使用一张基本牌。”（实际技能栏使用牌面双引号。）

- 沿用用户之前确认的批次规则：同一次多张【杀】进入弃牌堆只获得1个战意，满额时本次只摸1张牌。
- 转化消耗1个战意，按 `game.roundNumber` 记录最近发动轮次。回合切换、技能暂时失效或失去后当轮重新获得均不刷新；下一轮自然恢复。临时“已用”标识于原生 `roundStart` 清除，仅作显示，不作为限次的唯一依据。
- 点击入口的 `direct` 搭配零素材 `filterCard/selectCard`，由本地引擎 `GameEvent.backup()` 与 `checkEnd.autoConfirm` 立即进入牌名选择。
- 选牌使用原生 `chooseButton`，`select: [0, 1]` 避免全局自动确认设置导致选中即提交；`filterOk` 校验恰好一项且资源、轮次、原询问和牌名/属性合法。`fanPairedConfirm` 保留确定与取消，未选齐时确定置灰。
- 选牌确认后使用原生转化 backup，主动【杀】继续手选目标并手动确认；打出【杀】或响应【闪】无目标待选，直接提交。桃酒依照本地 `selectTarget`、`notarget` 等规则判断是否已确定目标，原生处理自用或濒死救援目标，不手工改选。
- 固定目标的自动提交在原生检查完成并暂停后执行微任务，再验证事件、技能、资源、轮次、响应条件和 `game.check()`；零素材范围 `[0, -1]` 防止原生确认钩子在暂停前提前提交。离开事件、取消、失去资源或牌被禁用时不提交。
- 仅在最终 `precontent` 再次验证成功后支付1个战意并消耗本轮次数，随后播放既有转化语音一次；选牌、取消、重新选择或状态失效不播音。现有语音文件与随机池保持不变。
- 普通模式仅提供普通、火、雷【杀】，UI、最终确认与支付入口均限制特殊属性；其他牌仍保留原生次数、距离、禁用和目标检查。
- AI同步读取每轮记录，实体【杀】优先级稍高于消耗每轮转化的【杀】；焚天的资源预算不把本轮已经消耗的转化计入额外出杀。打出或救援选牌保留原生响应评估，主动用牌按原生使用收益判断。

`tests/mavuika-interaction.mjs` 直接复用本地 v1.11.6 的 `GameEvent.backup/restore`、`Check` 和确认钩子，覆盖入口、选牌/取消、取消选择后确认失效、主动杀目标、开关自动确认、打出响应、固定桃酒及救援目标、状态变化、轮次、支付与经典属性范围。`tests/mavuika-audio.mjs` 继续检查实际挂载触发器和语音节点，并验证同轮跨回合限次及次轮恢复；音频布局与台词测试复核原生路径、随机池、静音开关及文件哈希。

以上属于交互/规则模拟及真实方法体检查；尚未进行游戏界面点击、真实对局或联机实测。
